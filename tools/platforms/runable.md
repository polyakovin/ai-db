# Runable

Runable — проприетарная AI-платформа для создания и публикации цифровых артефактов через одного агента. Пользователь формулирует результат, а агент уточняет требования, предлагает план, выбирает инструменты и собирает готовый сайт, презентацию, отчёт, таблицу или мультимедийный материал.

## Модель работы

Базовый цикл платформы: `goal → clarification → plan → execution → review → export/deploy`.

| Режим | Назначение | Ограничения |
|---|---|---|
| **Agent Mode** | Создание артефактов, запуск кода и команд, web search, работа с файлами и медиагенерация | Модель выбирается как tier; создаётся sandbox |
| **Chat Mode** | Текстовые ответы и анализ загруженных изображений/PDF | Нет tools, web search, sandbox, branching и rollback |
| **Plan Mode** | Исследование, вопросы и согласование `plan.md` перед сложным исполнением | До подтверждения нельзя менять рабочие файлы, ставить пакеты и генерировать медиа |

Каждый Agent Mode-чат получает отдельный персистентный sandbox. Он сохраняется между сообщениями, позволяет писать файлы, запускать команды, устанавливать пакеты и поднимать серверы; после 45 минут бездействия sandbox приостанавливается.

## Типы артефактов

- full-stack сайты и мобильные приложения с deploy, базой данных, файловым хранилищем, аналитикой и Stripe;
- презентации, отчёты, таблицы и social-media carousels;
- изображения, видео, аудио и свободный canvas;
- исследовательские отчёты с web search, citations и Markdown-редактором.

Результаты можно экспортировать в PDF, PPTX, MP4, PNG, XLSX и CSV либо публиковать как сайт с собственным доменом.

## Agent harness

Runable объединяет несколько компонентов [agent harness](../../patterns/architecture-design/agent-harness.md):

- **skills** — преднастроенные workflow, которые агент выбирает автоматически или пользователь вызывает явно;
- **memory** — предпочтения бренда, тона и форматов между чатами;
- **sandbox** — изолированное выполнение кода и серверов;
- **human approval** — согласование плана до дорогого multi-step исполнения;
- **checkpoints** — rollback состояния чата, canvas и файлов после каждого ответа агента;
- **branching** — независимая копия разговора и sandbox для альтернативного направления;
- **RunClaw** — доступ к тому же агенту, памяти и кредитам из Telegram, Slack и Discord.

Branching не поддерживает merge, а rollback необратимо удаляет более поздние сообщения. Для рискованного эксперимента безопаснее сначала создать ветку.

## Модели

В Agent Mode конкретная модель скрыта за уровнями Lite, Pro и Max: выше уровень — глубже reasoning и больше расход кредитов. В Chat Mode можно выбрать конкретную модель от [Anthropic](anthropic.md), [Google Gemini](gemini.md), [OpenAI](openai.md) или xAI. Список доступных моделей меняется, поэтому его нужно проверять в актуальной документации.

## Цены и доступ

Runable использует подписку и кредиты. Кредиты списываются за все AI-операции; расход зависит от model tier, объёма контекста, сложности, разрешения и длительности медиа. Неиспользованные месячные кредиты не переносятся, а прямое редактирование на canvas заявлено как более дешёвый путь по сравнению с повторной генерацией через чат.

На 2026-07-20 публичная pricing-страница и раздел Plans & Credits в документации расходятся по названиям тарифов и лимитам. Поэтому перед покупкой нужно сверять live pricing и checkout, а не полагаться на сохранённые числа из обзоров.

## Open Source статус

Основная платформа закрыта и предоставляется как SaaS. У организации Runable на GitHub есть отдельные открытые компоненты — mobile automation, MCP server, browser CLI, memory skill и sandbox-related repositories, — но публичного репозитория полного продукта нет.

## Сильные стороны и ограничения

**Сильные стороны:**

- один outcome-driven интерфейс для разных типов артефактов;
- явный plan approval для сложных задач;
- персистентный sandbox, snapshots, rollback и branching;
- точечное ручное редактирование результатов без полной перегенерации;
- доступ к агенту через web и мессенджеры.

**Ограничения:**

- закрытая платформа и credit-based стоимость затрудняют прогноз бюджета;
- mode и model tier нельзя менять внутри уже начатого разговора;
- ветки нельзя объединять, rollback нельзя отменить;
- маркетинговые числа по пользователям, benchmark и connectors требуют независимой проверки;
- независимых долгосрочных отзывов пока мало, а отдельный hands-on обзор сообщает о неясности credit accounting и сбоях Discord channel mentions в апреле 2026 года.

## Когда рассматривать

Runable подходит командам и создателям, которым важен единый workspace для быстрого получения редактируемых визуальных и web-артефактов без сборки собственного agent stack. Для воспроизводимых engineering-workflow, строгого контроля моделей, self-hosting или предсказуемого unit economics предпочтительнее инструменты с открытым runtime и явной тарификацией.
