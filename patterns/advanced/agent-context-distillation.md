# Агентная компрессия контекста (Context Distillation)

## Проблема

В длинных агентных workflow контекст разрастается из-за:

- длинной истории рассуждений;
- промежуточных выводов на каждом шаге;
- пересылки состояния между subagents и рантаймами;
- многократных retries и восстановлений после ошибок.

Если всё это хранить в неизменном виде, растёт стоимость и падает сигнал-noise.

## Решение

Ввести **context packet** между шагами:

1. После каждого критического шага агент делает структурированную дистилляцию состояния.
2. Packet хранит:
   - `scope` (что именно рассматривается);
   - `facts` (что подтверждено);
   - `assumptions` (что осталось неуточнённым);
   - `open questions` (что нужно проверить);
   - `next actions` (очевидный следующий шаг).
3. Прежде чем продолжать, packet проходит верификацию:
   - автоматические проверки по домен-правилам;
   - контрольные вопросы (например, можно ли восстановить исходный смысл из сжатого описания);
   - сравнение с эвристиками `coverage`.
4. При необходимости packet декомпрессируется моделью в локальный контекст для каждого шага.

Дополнительно полезно хранить "сырой сырьевой лог" отдельно, но подгружать его только по необходимости.

## Когда применять / Когда не применять

**Применять**

- когда workflow многопоточный или multi-agent и нужен handoff между ролями;
- когда есть высокий ratio `context window cost`;
- когда задача состоит из этапов checkpointing.

**Не применять**

- когда задача короткая и не требует повторных проходов;
- когда высокая цена потерять формулировки (юридика, compliance, safety policy); тогда packet должен включать полный trace или двойной слой (compressed + raw excerpt).
